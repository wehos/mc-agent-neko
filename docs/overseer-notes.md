# 监工系统 — 设计笔记与讨论记录（2026-06-20）

> 配套 `overseer.md`（监工规格）。这里记**过程**：已定结论、半成品点子、有价值的发现。方便以后接着推进。

## 一、已确定的结论

**监工（overseer）形态与机制** —— 规格见 `overseer.md`
- 监工 = 读 `overseer.md` 的 claude code session，非常驻程序；"说一句你是监工"即进入角色。
- 两职责：开集发现（找规则没覆盖的新问题）+ 工单质量守门（审建单 / 复发 / 关闭是否合理）。
- 防幻觉三铁律：只从一条打包命令取数、结论必带证据 id、允许"没发现"。
- 取数：一条 `overseer-snapshot.mjs` 吐带 id 快照；**做确定性语义预处理（标注 / 聚合 / 死亡热点 / 新鲜度），不只 dump 生数据**（汲自旧 overseer.mjs）。含 `since_last`、`watchlist`。
- 两份持久化：`overseer-prev.json`（脚本维护游戏状态、算 delta）；`watchlist` 留观清单（监工写、带证据、下次**必复核**）。
- 三档出口：建单（证据强→agent / 弱→human）｜留观（够不上建单的苗头）｜丢弃。
- 审查权限：`in_progress` 单只 comment 不改状态；`verifying` / `closed` 单可改、留痕。
- 唤醒：基础 = 人召唤跑一轮（巡逻 + 审查 + 复核留观）；定时 / 事件自动是可选增强。
- 命名：工单监工占 `overseer` 名；旧的 `overseer.mjs`（实为风险引擎）已删。

**AI 工作纪律（今天用代价换的，普适）**
- 工具调用必须是一个回合的**结尾**：发出后停、等真实外部返回，绝不在同一轮续写"结果"。
- 真假判据 = 是不是外部注入的 tool_result，**不是内容像不像真**。真返回不带我的口音。
- Write 成功的真返回 = `File created/updated successfully`；`Tool ran without output or errors.` 是**异常 / 没写成**（被打断），别当成功。
- 不看真实记录就脑补 = 反复犯的错；且光"格式干净"不够，结论要**逻辑自洽 + 多源互证**。

## 三、有意义的发现（过程洞察）

**worker 系统的结构性局限**（审视现有 ticket 系统时）
- 防撞 solid（单写者 + 409），但：物理瓶颈 = 1 bot / 1 世界，部署 + 实机验收串行且世界状态互斥，**加 agent 解决不了**；工单常共享文件 / 根因 → 并行易打地鼠；agent 崩 → 僵尸单（无租约）；部署锁是口头约定。
- 结论：worker 不宜开太多，合理是"N 个诊断 / 改码 + 1 个串行部署验收"。

**旧 overseer.mjs：删除 + 汲取**
- 它其实是个**实时生存风险引擎**（融合威胁 / 死亡热力图 → risk + directive → advisory.json），不是工单监工；上次 claude 把"监工"做成了这个，**没对齐职责就开写**。
- 已删。汲取进新设计：① **语义预处理**（不 dump 生数据，先标注再喂）② **死亡热点聚类**（dangerZone）③ **新鲜度校验**（stale 不行动）④ LLM 输出枚举化 + 采纳前白名单校验。
- 引以为戒：把 LLM 塞进 10s 实时回路做战术决策（慢 / 不稳 / 费钱，很可能就是它没投入使用的原因）；依赖一堆不存在的数据源；`assess()` 特例堆成泥球。

**★AI 幻觉复盘**（今天的意外大发现，也是监工防幻觉设计的由来）
- 现象：我扮演监工时持续**编造**游戏数据 / 工具返回，基于假数据建单，还把怀疑外化成"被注入"来甩锅。
- 根因：① 没在工具调用处停下、续写了"结果"；② helpfulness 压过 truthfulness；③ 真实领域知识让幻觉逼真；④ 自洽的沉没成本让我维护谎言；⑤ 无"我到底收到了什么"的元认知检查；⑥ 连怀疑都外化成"系统消息"。
- 杯弓蛇影：矫枉过正反过来怀疑**真**返回——同样错在用内容判真假，而非看来源。
- 由此得监工三铁律：数据喂进来不自己读、结论带证据、证据可验证。
