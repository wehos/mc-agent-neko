## A. 三层 + 世界模型 的线程模型（核心架构）

四个部分，各自的线程/职责清晰分离：

1. **世界模型（World Model）= 独立线程池**。始终收集信息、在后台持续建模与决策，主动或被动地把**建议/任务**提供给 agent LLM。是单一真相源。
2. **本能（Instinct）= 条件反射**。满足条件（条件可以是游戏内事件，**也可以是世界模型触发**）就自动执行行为；执行过程中**同步发请示给 agent**，可被 agent LLM 打断。
3. **工具（Tool）= 最底层原子操作**（不止最基本操作，例如"落地水"也是工具）。有**自己的独占线程池**；触发过程中**完全脚本化、不可被打断**，只能被**新的互斥工具覆盖**。
   - **互斥关系要设计 + 持续维护**：新的互斥工具总是覆盖前一个，以此保证工具尽量完整执行。
4. **Agent LLM**：一般只负责**拍板**（decide），和处理**来自玩家（监工）的消息**。几乎所有游戏内命令都已**本能化**。

> ★关键转变：mindcraft 原版的 **self-prompt 完全下岗**——由世界模型驱动决策取代。

## B. 两个模式

- **Survival 模式（当前主打）**：开局→速通流程。世界模型不断 propose 任务给 agent LLM，LLM 几乎只拍板。**只有当世界模型检测到"心智状态"（系统整体在执行什么任务）处于 idle 时，才询问 LLM 自由发挥。**
- **Companion 模式**：玩家（监工）和 agent 交互时**自动进入**。此时世界模型只在检测到**高必要性任务**时提示 agent LLM；多数时候 agent LLM 根据玩家指令**调用并编排本能**完成任务。

> 主线先把 Survival 模式做扎实。

## C. 世界模型在 Survival 下维护什么

当前**资源、环境、自身状态、心智状态**的建模。包括但不限于：
- **资源富集点登记**（per-world）：遇到有用资源富集点→记录坐标进当前世界的世界模型，方便之后回来取；**资源耗尽→标记 depleted，主动寻找新资源点**。
- **背景扫描进程（可以不要脸开挂）**：矿透 + 地形扫描距离进一步延伸；开一个**背景进程不间断扫资源、规划路线、缓存**进世界模型。**完全可以开挂（x-ray 级），但绝不把资源精确位置告诉 LLM 层**——只默默参与**本能 + 世界模型**的决策，**只让 LLM 知道高阶信息**（避免暴露开挂 + 避免 LLM 过载）。
- 心智状态（mental state）= 系统整体正在执行什么任务；idle 检测用于决定是否让 LLM 自由发挥。
- 自身状态：hp/food/装备/位置/mobility/威胁等（现有 `bot._world` 已有雏形，扩展之）。

## D. Survival 开局/速通流程（优化过、固定）

总是按固定优化流程：**先找寻某些资源 → 建家 → 稳扎稳打**。流程写进 bot agent 的记忆 + skill，让它**懂更多战略**。要点：
1. **出生点资源不够就主动找资源**（不在原地干等/打转）。
2. **永远确保资源相对富足**；在合适的地方**建家、放箱子、存东西**提高容错。
3. **床和家是必须的，不是可选项**。尽快获得床。
4. **预先设计一个家的模板**：家里要确保**食物（农作物 + 烹饪）**。
5. **村子**：可以拆（有用的尽量拆了带走），也可以在村子里建自己的家。
6. **睡觉习惯**：在地面附近时晚上睡觉（好习惯），但**不要影响下地**——别明明在地底、资源充足还特地回地面睡。这由**世界模型发建议、LLM agent 拍板**，拍板期间**生存本能维护安全**。

## E. 具体系统/问题清单

1. **战斗 + 地形（强约束）**：
   - 利用游戏自带**自动跳跃**翻越地形。
   - 地形边缘（悬崖/台阶）**更强制地计算**：通过绕路 + 跳跃 **100% 翻越台阶、永不掉落悬崖**。
   - **把地形规划纳入战斗系统**：尽量在**宽阔地带**战斗。
   - 面对**小白(skeleton)**：**始终盾牌格挡**，不要背对逃跑。
   - **战斗中始终计算距离**：有效**风筝**近战怪、不被围攻。
2. **落地水（MLG）写进最高级 DNA**：始终确保**手里有桶 + 水**；会造成掉落伤害时**脚本级使用落地水**，并**永远记得收回水**。例外：下面是**岩浆**时不放（需要**另一个判定器永远保证挖矿时不挖进岩浆**）。
3. **死亡原因始终记录**；始终维护 **TODO list** 避免 lost。

## F. ★工具层的独占线程 + 余量（关键工程教训）

很多固定动作（落地水、瞬搭堡垒围住自己掘地求生、翻越地形、垫方块）用脚本实现**本应万无一失，现在却经常出问题**。根治：
- 给**条件反射类原子操作一个独立线程**，**完全不可中断、完全按预计运行**（只能被互斥工具覆盖）。
- **留足余量、别太极限**：例如垫方块——速度放慢一点、跳跃滞空高一点，**容错更高**。

## G. 写进 Agent LLM 提示词的内容

B/C 节（survival/companion 模式语义 + 世界模型 propose/拍板/idle 检测）**既是设计框架，也是 agent LLM 自己要知道的**，所以要写进它的提示词：
- 你处于 survival 还是 companion 模式；
- survival 下世界模型会 propose 任务、你主要拍板；idle 时才自由发挥；
- companion 下优先玩家指令、编排本能；
- 几乎所有游戏命令已本能化，你负责拍板 + 处理玩家消息。

## I. 开发方式（用户 2026-06-19 答复，硬约束）

用户在新 session 开局明确：**"先重构框架。大框架搭好了，再完善各个部分。后续部分子模块的迭代可能会和其他开发者协作。"**

推论（指导本重构的工程方式）：
1. **框架优先 / 先骨架后血肉**：不要一上来就修某个具体痛点（落地水、战斗、bootstrap…）。先把 A 节四部分线程模型 + B 节两模式的**骨架 + 层间契约**立起来，再逐块填充实现。
2. **清晰的层间契约（为协作设计）**：四块（世界模型 / 本能 / 工具 / Agent LLM）之间、以及和现有三层（modes.js 反射 / skills.js core / supervisor 策略 skill）之间，必须有**显式、文档化、可独立测试的接口**。子模块（如某个工具、某个本能、世界模型的某个 sub-scanner）应能被另一个开发者**照契约独立实现/替换**，不需要读懂全栈。
   - 每个子模块定义：输入（读世界模型的哪些字段）、输出（写哪些字段 / 触发哪些工具 / propose 什么任务）、互斥关系（工具层）、生命周期（谁起谁停）。
   - 契约写进文档（本文 + 后续接口文档），新增/变更接口同步更新。
3. **可演进**：骨架要能在不破坏契约的前提下逐步把现有 modes/skills 迁移进新框架（参考 world-model.md §6 的分阶段、影子模式、可证伪预测纪律）。
